# ADR 0007: Remote LLM for content generation

- Status: accepted
- Date: 2026-10-26

## Context

The learner was given access to the Alliance (Digital Research Alliance of Canada) inference
gateway at `inference.vulcan.alliancecan.ca`. It is OpenAI-compatible and serves
`gpt-oss-120b`, a far larger model than the local Gemma 4 12B. Most of what Haiku caught in
Gemma's lessons was model quality: wrong answer keys, invented idioms, wrong agreement. A full
lesson takes about 2 minutes on the gateway, compared with 5–8 minutes on the Mac. It also
frees the Mac's 16 GB.

## Decisions

- **Only content generation goes remote.** Covered: lessons, verb and vocabulary banks, and
  review-set extras. `AUTHORING_LLM=remote|local` in `.env` selects
  `inference.providers.get_authoring_chat_model()`. Grading and the tutor always use the local
  LLM, so studying never depends on the gateway. Setting `AUTHORING_LLM=local` restores the
  Gemma pipeline unchanged.
- **The key lives in `.env`** (gitignored) as `AUTHORING_LLM_API_KEY`, and so does the original
  `aleph_creds.txt`.
- **gpt-oss is a reasoning model:**
  - requests send `reasoning_effort: low` (configurable);
  - each request's `max_tokens` gets 4,000 extra tokens for the hidden reasoning;
  - the client waits out `503 model_scaled_to_zero` responses using `Retry-After`, for up to
    4 minutes;
  - JSON-schema `response_format` works (tested), although the gateway doesn't document it.
- **External proof-read: off at first, then back on, with Sonnet.** `AUTHORING_EXTERNAL_REVIEW`
  defaults to false for a remote author. The first batches ran without it. Then Haiku found
  3–13 real errors in each of the 7 hardest drafts, mostly in explanations, tables, examples and
  glossaries, which the self-checks below never see. Nine auto-published lessons also translated
  « dîner » as dinner. So the learner turned the proof-read back on, with Claude Sonnet as the
  reviewer (`AUTHORING_EXTERNAL_REVIEW=true`). `content_review_export --published` exports
  lessons that were published without it; their findings become revision jobs.
- When the proof-read is off, `authoring.services.auto_review` runs after each job:
  - **publish** when there are no deterministic errors, no unverified Québec claims and no
    AI-critic flags;
  - **revise** otherwise, with the problems as notes, up to 4 generations;
  - after that, **leave it in Admin**.
- **A solver joins the critic.** The authoring model answers every multiple-choice and
  comprehension question without its key. If the options it judges correct aren't exactly the
  key, the question is flagged and revised. Wrong keys were the commonest error in generated
  lessons, and the sentence critic can't see them. The critic schema now opens with
  `correct: bool`, because gpt-oss filed "no problem" as an error entry.
- **gpt-oss habits handled deterministically:**
  - Markdown `**bold**` and `A.` / `1️⃣` numbering are stripped from exercise fields
    (explanations keep bold);
  - duplicate accepted answers are merged;
  - draft fields have length limits and descriptions, because it once put a whole exercise
    into the `prompt` field;
  - answers with notes in brackets, and text that leaks the generation instructions, are errors.
- **Up to 3 generation workers** (`WORKER_REPLICAS`): the gateway serves requests in parallel.
  `recover_jobs` only requeues jobs that have shown no progress for 10 minutes, because another
  worker may be running the rest. Jobs wait and retry when the LLM is unavailable.

## Consequences

- Learning content is sent to, and generated by, an external service, which this project
  avoided until now. It covers content generation only, and the learner chose it.
- With no independent reviewer, the author also checks its own answer keys, so errors that come
  from the model's own blind spots can pass. In the first test, a question accepted only
  « Après le souper » although « dîner » and « déjeuner » fit equally well. Set
  `AUTHORING_EXTERNAL_REVIEW=true` to put the proof-read back, as the learner did.
